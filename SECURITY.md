# Security Policy 🛡️

The **Modern Termux:MOTD** project takes the security and privacy of its users very seriously. As an official companion application integrated into the [Modern Termux](https://github.com/Furkan00487/modern-termux) ecosystem, maintaining a robust security boundary and protecting the local terminal environment is paramount.

---

## 📌 Supported Versions

Only the latest official release and the active `master` branch receive security patches and maintenance updates. We strongly encourage all users to keep their installations updated.

| Version | Supported | Description |
| :--- | :---: | :--- |
| `master` branch | ✅ | Mainline development and active security fixes |
| `1.2.x` (Latest) | ✅ | Current stable production release |
| `< 1.2.0` | ❌ | End of Life (Unsupported — please upgrade) |

## 🛡️ Security Architecture & Threat Model

### 1. Rootless Local Execution (`sharedUserId="com.termux"`)
* **Shared UID Model:** Modern Termux:MOTD declares `android:sharedUserId="com.termux"`. Under the Android Security Framework, this allows the application to run with identical Linux UID/GID privileges (`u0_a351`) as Modern Termux when signed with the exact same official Release Keystore.
* **Sandbox Boundary:** The app communicates with the terminal environment strictly via local filesystem writes (`~/.termux/motd.sh`) and explicit local broadcast intents (`BatteryReceiver`).
* **Cryptographic Isolation:** Applications not signed with the official Modern Termux signing key cannot request or share this UID, preventing untrusted applications from accessing terminal storage.

### 2. Zero Network Footprint (100% Offline by Design)
* **Zero Internet Permissions:** The application deliberately omits `android.permission.INTERNET` from its manifest.
* **Zero Telemetry / Zero Tracking:** No analytics, metrics, tracking identifiers, or background network calls exist in this codebase. All MOTD generation and preview rendering occur entirely in-memory and on-device.

### 3. Shell Script Generation Security
* MOTD scripts generated by this application are executed during interactive terminal login sessions (`~/.termux/motd.sh`).
* User-provided text inputs (titles, subtitles, custom command shortcuts) are strictly structured and written directly to local shell configurations.

## 🚨 Reporting a Vulnerability

If you discover a potential security vulnerability, privilege escalation flaw, or unintended code execution pathway, please disclose it to us **privately and responsibly**.

> [!CAUTION]
> **Do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

### Preferred Reporting Channels:
1. **GitHub Private Vulnerability Reporting (Recommended):**
   * Open a confidential advisory report directly through [GitHub Security Advisories](https://github.com/Furkan00487/modern-termux-motd/security/advisories/new).
2. **Direct Security Contact:**
   * If GitHub Security Advisories are inaccessible, contact via email: `furkan00487@users.noreply.github.com` with the subject tag `[SECURITY VULNERABILITY] Modern Termux:MOTD`.

---

## 📋 What to Include in Your Report

To help us investigate, triage, and patch the issue promptly, please include:
* **Description:** A detailed explanation of the vulnerability, affected components, and potential attack vectors.
* **Reproduction Steps / Proof of Concept (PoC):** Step-by-step instructions or minimal reproduction scripts.
* **Environment Details:**
  * Modern Termux:MOTD version (`versionCode` & `versionName`)
  * Modern Termux core app version
  * Android OS version and device architecture (`arm64-v8a`, etc.)
* **Impact Assessment:** The expected real-world impact if exploited (e.g., unauthorized file modification, intent spoofing).

---

## ⏱️ Response & Disclosure Process

* **Acknowledgment:** We aim to review and acknowledge incoming security reports within **48 hours**.
* **Investigation & Triage:** We will validate the issue in an isolated environment, assess severity, and keep the reporter informed.
* **Fix & Verification:** Patched builds are verified against automated unit test suites and signed keystore validation.
* **Coordinated Disclosure:** We adhere to Coordinated Vulnerability Disclosure (CVD). Once a patch is finalized, a new signed release will be published alongside a GitHub Security Advisory crediting your responsible disclosure (unless anonymity is requested).

## 🔑 Signature & Build Authenticity Verification

Official releases are cryptographically signed using the official Modern Termux Release Keystore. Users and auditors can verify the authenticity and integrity of downloaded APKs:

```bash
apksigner verify --verbose --print-certs termux-motd_v<VERSION>-github-release_arm64-v8a.apk
```

**Expected Signer Digest:**
* **Signer DN:** `CN=Termux Release, OU=Termux, O=Termux, L=Unknown, ST=Unknown, C=US`
* **Certificate SHA-256:** `728d1490f7eddcf0c0783d8a2aba5195214648409664c4cf18185edda5dc78a7`
